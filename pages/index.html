H1: 20/10-day channel breakout, BTC/EUR 4h, long only

A Turtle-style channel breakout run in Freqtrade, tested on train, validation and one held-out period against buy-and-hold. All results are historical simulations. No paper-trading or live results exist yet.

Summary

  • Held-out, base costs: net +39.8 % vs +17.6 % for buy-and-hold; max drawdown 30.4 % vs 52.2 %; in the market 38.5 % of the time, so part of the smaller drawdown is simply lower exposure.
  • The sample is small. 14 trades, 5 winners; mean trade +2.8 % (s.d. 14.5 %), t ≈ 0.73. The mean is not distinguishable from zero.
  • Returns are concentrated. The two largest trades add +65.5 pp; the other twelve sum to −25.8 pp.
  • It lags in strong trends. Validation: +67.2 % vs +265.2 % for buy-and-hold, at a similar drawdown (20.6 % vs 20.5 %).
  • Gate: the four predeclared criteria pass, the drawdown criterion by 0.94 pp, on the second held-out run (the first run broke the sizing rule and failed). The pass only permits forward paper trading and a €10 execution test.

Mean, s.d. and t are computed from the per-trade returns in the recorded trade list. The concentration figures add those returns; on the fixed stake they sum to +39.6 pp, against the recorded net return of +39.8 %.

Protocol

Rules, periods, costs and pass criteria were fixed in research/hypotheses/H1.md before the evaluation data was inspected. The strategy file was frozen before the held-out run (SHA-256 142f95a4…70d7fc8e). Train was used as a sanity check only; no parameter was selected on any period.

Decision rule: all four must pass

K1Held-out net return, 0.5 %/side> 0+39.81 %39.81 pppass

K1, K3 and K4 only require a positive return; they do not test against the benchmark or against zero with any significance level. K2 is the binding criterion.

Deviation from protocol

The first held-out run used a compounding stake (stake_amount: "unlimited") instead of the declared fixed stake. It returned +32.25 % with a 35.11 % drawdown and failed K2. After review flagged the mismatch, every period was re-run with the fixed stake and no other change. The held-out window has therefore been evaluated twice, and the second run is the one that passes. Both are published.

Limitations

  1. Low power. 14 held-out trades cannot separate a small edge from noise; the mean-trade t-statistic is about 0.7.
  2. Reused held-out data. The held-out window was evaluated twice (see above). It is spent; new evidence must come from data after 2026-09-24.
  3. Selection with hindsight. The hypothesis was written by an AI model whose training covers crypto prices up to mid-2026. Choosing a trend follower for this market may itself be informed by the test period. Only the 20/10 channel lengths come from the literature.
  4. One asset, one path. A single pair and a single price history. ETH/EUR was run as a robustness check on train + validation only.
  5. Execution is modelled, not observed. Fills at next bar open with a flat cost per side; no order-book depth, partial fills or outages. The proxy check covers prices, not fills.
  6. Benchmark choice. Buy-and-hold at 100 % exposure is a weak comparison for a strategy that is in cash about 60 % of the time. An exposure-matched or volatility-matched benchmark was not predeclared.

Next: forward paper trading on the target VPS, then a €10 live execution test to measure real fills and fees. Neither has started. Full details are in the experiment record and ADR-0005.

System

Freqtrade 2026.8, pinned by image digest, is the only component that places orders. The tracked configuration is spot, dry-run, without exchange credentials, and starts in stopped. Target host: Debian 13, 2 vCPU, 3 GB RAM.

  • No project code calls an order-creating method; a test enforces this.
  • The optional Jev model filter can only block new entries, fails closed, and has no credentials. It has no provider yet.
  • systemd timers for restic backups and a dead-man's-switch health ping; restores come back stopped.
