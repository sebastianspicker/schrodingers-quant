# H2 — H1's signals with volatility-targeted sizing (BTC/EUR, 4h)

**Status:** predeclared 2026-10-08, before any forward data exists. Changes
after this date require a new hypothesis ID (H3, …), not edits. H2 has not
been run on any data; see "Evaluation" for why its backtests are reported only.

## In short

- **What is tested.** Whether sizing each H1 trade by recent volatility, so
  that every position carries about the same risk, improves H1's return per
  unit of drawdown without changing when it trades.
- **How it is judged.** On forward data only, paired against H1 on the very
  same trades, once 30 trades have closed. Three criteria (H2-1 to H2-3).
- **What a pass allows.** Replacing H1's fixed stake with H2's sizing in the
  dry-run configuration, and nothing more. It is not a capital decision.

## Claim

H1's drawdown is smaller than buy-and-hold's, but mostly because it is in the
market less, not because of when it is in
([ADR-0006](../../docs/adr/0006-evidence-standard.md)). A fixed € stake
gives every trade a different risk: the same −20 % stop is hit after a modest
move in a turbulent market and after a large one in a calm market, and the
marked-to-market drawdown is dominated by the turbulent trades. Sizing the
stake inversely to recent volatility, a standard practice in systematic
trading, should lower the drawdown more than it lowers the return, raising the
return per unit of drawdown (Calmar ratio).

In plain terms: trade smaller when prices have been jumping around, trade the
full stake when they have been calm, and enter and exit exactly as H1 does.

## Rules (fixed; no tuning)

| Item | Rule |
| --- | --- |
| Signals, exits, stop, protections, market, timeframe | Identical to [H1](H1.md): 120/60-candle channel breakout, −20 % catastrophe stop, the same three protections, Kraken spot BTC/EUR, 4h closed candles. |
| Notional | N = the configured stake amount (research: €1,000; dry-run: the configured stake), the same reference as H1's fixed stake. |
| Realized volatility | σ̂ = standard deviation (ddof 1) of the 120 log returns of closed 4h candles ending with the signal candle (20 days; the signal candle is closed when the decision is taken), annualised with √(6 × 365). |
| Target volatility | σ* = 40 % a year. |
| Stake | stake = N × clip(σ* / σ̂, 0.25, 1.0). The full stake in calm markets; a quarter of it at the most turbulent; never more than N (no leverage). |
| Sizing time | Computed once, at entry, from candles closed at or before the signal candle; the entry candle's close is never used. Never adjusted during a trade. |

Why these numbers: 40 % is at the low end of BTC/EUR's realised volatility over
2020–2026 (calm stretches in 2023–24 ran at roughly 35–60 %), so the cap of 1.0
binds in calm regimes and the sizing acts in turbulent ones. The 120-candle
window matches H1's entry channel so that both rules see the same history. The
floor of 0.25 keeps a €1,000 notional's smallest stake at €250; at the €8
dry-run stake it would be €2, below Kraken's cost minimum, which is why H2 is
evaluated offline on the notional and not through the bot's stake (see
"Known limits"). All three were chosen by
reasoning on 2026-10-08, by an author who knows BTC price history up to then;
that is the same limitation H1.md records, and the reason H2 is judged on
forward data only.

## Evaluation

Because H2 does not change the signals, it opens and closes exactly the trades
H1 does; only the stake differs. H2's result on any window can therefore be
computed from H1's trades on that window and the candles, without running a
second bot. This is how H2 is evaluated:

- **Backtests on train and validation (2020-01 → 2024-06)** are run with
  `research/strategies/H2VolTargetBreakout.py` through the research pipeline
  and reported in `research/experiments/H2/`. They are a sanity check of the
  implementation. They are not evidence, and no parameter is changed in
  response to them: the periods overlap H1's development, and
  [ADR-0004](../../docs/adr/0004-h1-no-go.md) spends the 2024-07 → 2026-09
  window for every successor hypothesis.
- **The forward window is the test.** H1's dry-run trades after 2026-10-08
  ([forward test protocol](../../docs/forward-test.md)) are re-sized with the
  rule above, from the same candles, and both equity curves are marked to
  market on the fixed notional with `sq.research.metrics.equity_curve`. This is
  `sq.research.h2.paired_evaluation`, run by every forward report
  (`h2_paired` block).
- The comparison is **paired**: same trades, same dates, same costs. Only the
  sizing differs, which removes the noise of comparing two different trade
  lists and is why a 30-trade sample can say something here that it cannot
  say about H1's edge.

## Protocol v2 amendment, 2026-10-08 before deployment

[ADR-0007](../../docs/adr/0007-trader-workbench.md) corrects the evaluation
contract before any forward evidence exists. Full candle warmup is retained
outside the performance window. Every baseline trade is normalized to €1,000;
the stake decision uses the information available at original order submission.
Missing sizing history or non-PASS F1/F2 withholds a decision. `all_pass` is raw
arithmetic only; the machine-readable `judgement_allowed` and `verdict` govern.
If both return/drawdown ratios are undefined, the result is INCONCLUSIVE;
identical no-drawdown curves do not demonstrate improvement.

## Decision rule (forward window, once F4 of the forward protocol is met)

- **H2-1** H2's marked-to-market max drawdown ≤ H1's on the same window.
- **H2-2** H2's return / max drawdown exceeds H1's by at least 0.2 (for
  example 1.5 against 1.3). A multiple of H1's ratio would reward H2 for being
  worse when H1's ratio is negative, so the margin is absolute. If H2 has no
  drawdown at all and H1 does, H2-2 passes when H2 return is positive.
  If neither has drawdown, the comparison is INCONCLUSIVE.
- **H2-3** H2's net return > 0 at realized costs.
- **GO** if all three pass: H2's sizing replaces the fixed stake in the dry-run
  configuration (a new ADR), and the live pilot, if any, uses it. GO does not
  justify adding capital.
- **NO-GO** otherwise. A result where H2-1 passes and H2-2 fails is recorded
  as "sizing reduced drawdown at the cost of return" and closes H2.
- If H1's forward run stops for F3 before 30 trades, H2 is judged on the
  closed trades available only if there are at least 20 and F1/F2 both pass; otherwise it is
  **INCONCLUSIVE** and waits for the next window.

## Costs and metrics

As H1: 0.5 % per side base, 1.0 % stress; net return, CAGR, marked-to-market
max drawdown, return / max drawdown, trade count, exposure; plus the
statistical assessment of `sq.research.statistics` on both curves.

## Known limits

- H2 inherits every limitation of H1's signal. It cannot create an edge; it
  can only change how much of it, or of its noise, is taken on per trade.
- The per-trade risk is still not constant: the −20 % stop in price terms is
  unchanged, so the stake, not the stop, carries the adjustment.
- Realized volatility over 20 days is a noisy forecast of the volatility of
  the coming trade.
- At the €8 dry-run stake the floor would be €2, below Kraken's cost
  minimum; the strategy then raises the stake to the exchange minimum, so the
  rule is not applied as written at that stake. The forward evaluation is
  therefore done offline on the €1,000 notional (`sq.research.h2.paired_evaluation`,
  reported in every forward report as `h2_paired`), not on the bot's stake.

## Glossary

| Term | Meaning here |
| --- | --- |
| Volatility targeting | Choosing a position size so that the position's expected price fluctuation is roughly constant from trade to trade. |
| Realized volatility | How much the price actually fluctuated over a past window, annualised. |
| Log return | ln(close / previous close); the standard input for volatility estimates. |
| Return / maximum drawdown | Window return divided by maximum drawdown; not annualized Calmar. |
| Paired comparison | Comparing two treatments on the same cases, here the same trades, so that only the treatment differs. |
| clip(x, a, b) | x limited to the range a ≤ x ≤ b. |
